# Provision Wi-Fi from the PC client (the PC needs Bluetooth)

<font>Note: this method is still in testing and may be unstable. If it fails, end provisioning and start again, or use another method.</font>

**<font>Note: BLE and Wi-Fi are mutually exclusive. They cannot be used at the same time. After provisioning succeeds, the device turns Bluetooth off, so Bluetooth is unavailable. To control the device over Bluetooth again, switch it to BLE mode. Wi-Fi disconnects when you do that.</font>**

**<font>Note: if you want the default Wi-Fi, do not provision. Default name: easysmart. Password: 11111111. The device connects to that network by itself.</font>**

1. Open the PC client, go to Device management, click Device tools, then Device provisioning.

![Open device provisioning from Device tools](./img/pc-blufi-provision/00-device-tools.png)

2. Enter the 2.4G Wi-Fi name and password, then click Start provisioning. Check the name and password carefully. The device does not support 5G Wi-Fi.

![Enter the Wi-Fi name and password](./img/pc-blufi-provision/01-enter-wifi.png)

3. The client scans for nearby devices whose names contain `BLUFI`. Find the device in the list and click Select.

![Select a BLUFI device](./img/pc-blufi-provision/02-select-blufi.png)

4. The client connects and writes the Wi-Fi settings. Keep the device powered and wait. Do not close the provisioning window.

![Writing Wi-Fi settings](./img/pc-blufi-provision/03-provisioning.png)

5. When you see Provisioning succeeded, click Done. If the firmware reported an IP address, the success page shows it. A missing IP does not mean provisioning failed.

![Provisioning succeeded](./img/pc-blufi-provision/04-provision-result.png)

After success, the device turns Bluetooth off and comes online over Wi-Fi. In the device list, a connection type of `MQTT` means the device is on Wi-Fi.

![Device online over Wi-Fi](./img/pc-blufi-provision/05-device-online.png)

If no `BLUFI` device appears, restart the device, end provisioning, and scan again.
